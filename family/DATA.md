# 规则记载方式（先不用数据库）

这一版是**后台体验包**：灵感可以随便加。玩法数字全部写在仓库的 JS 表里，运行时事件写进内存数组。原型阶段**不要上数据库 / 不要上独立 codebase 服务**。

## 结论

| 东西 | 记在哪 | 要不要库 |
|------|--------|----------|
| 职业种类、底薪、学历门槛 | `family/data/game-data.js` → `JOBS` | 否 |
| 灵感能买什么 | 同上 → `SHOP_ITEMS` | 否 |
| 工资公式、职级名 | `family/data/economy.js` | 否 |
| 随机事件 / 特殊事件模板 | `family/data/events.js` | 否 |
| 已经发生过的事 | 运行时 `state.eventLog`（内存，刷新即空） | 否 |

改规则：改对应 JS 文件，刷新页面。人多、要云存档、要运营在后台改权重时，再把这几张表迁到 Postgres / JSON CMS。现在加库只会拖慢原型。

## 工资公式

写在 `calcSalary`：

```
月薪 = round( 底薪 × 学历 × 智商 × 工龄 × 职级 ) + tempBonus
```

- 学历：学前 0.75 / 小学 0.82 / 初中 0.9 / 高中 1 / 大学本科 1.18
- 智商：`1 + (iq - 50) / 250`
- 工龄：每年 +2.5%，最多算 12 年（`jobMonths / 12`）
- 职级：每级 ×1.15
- 网红再乘 `1 ± incomeVariance`
- 学生走学费，不走这套

每月先按当前公式发钱，再清掉当月 `tempBonus`。

## 特殊事件 vs 随机事件

- **随机**：表在 `events.js` 的 `RANDOM_EVENTS`，每月抽签，toast + 写入 `eventLog`。
- **特殊**：人生节点弹窗（升学/就业/恋爱/结婚/生子）+ `SPECIAL_EVENTS.promote`。模板在代码里，发生过的实例进 `eventLog`。

`eventLog` 每条：`year, month, kind, title, text`。界面「记事」Tab 倒序展示，最多留 80 条。
